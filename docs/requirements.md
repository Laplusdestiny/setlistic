# Setlistic 要件定義書

最終更新：2026-10-11（Claude Docs版 rev.16 から書き出し）

## 概要・目的

カラオケで歌える曲を自分で登録・タグ付けし、店でその場で多観点から探せるWebアプリを作る。曲マスタは事前に集めず、登録時にApple MusicのURLから必要な情報を取得する。

- サービス名：Setlistic
- URL：setlistic.laplusdestiny.com
- アイコン：紙のセットリスト（セトリ表）をモチーフにしたデザイン案を採用
- 利用者：当面は自分のみ。将来は友人数十人程度に使ってもらう想定（一般公開は想定外）
- 主な利用シーン：カラオケ店でスマホから「今日歌う曲」を探す。PCでは登録や整理をまとめて行う
- 提供形態：スマホとPCの両方に対応したレスポンシブWebアプリ（スマホはホーム画面追加でアプリ風に使える）

## スコープ

MVPは「URL貼り付けで登録し、タグと項目で探せる」ところまでとする。

| 区分 | 内容 |
| --- | --- |
| MVP | Apple Music URL貼り付けによる曲登録、キーワード検索登録、手動登録 |
| MVP | 基本項目・カスタム項目・フリーキーワードタグの付与 |
| MVP | 多条件の検索・絞り込み |
| MVP | ログイン認証とユーザーごとのデータ分離 |
| 今後 | Siriショートカットからの登録 |
| 対象外 | 曲マスタの事前収集 |
| 対象外 | DAM・JOYSOUNDの配信有無の自動取得（公開APIがないため。タグ画面から作れる「カラオケ機種」グループの DAM・JOYSOUND タグで手入力する） |

## 機能要件：曲登録

Apple MusicのURLを貼り付けると曲IDを抽出し、iTunes Lookup API（認証不要）で曲情報を取得して登録する。

1. 登録画面にApple MusicのURLを貼り付ける
2. URLをパースして曲IDを取り出す
   - `music.apple.com/{国}/album/{名前}/{アルバムID}?i={曲ID}` 形式
   - `music.apple.com/{国}/song/{名前}/{曲ID}` 形式
   - 国コード違い、追加クエリ（`?l=` 等）を吸収する
3. `itunes.apple.com/lookup?id={曲ID}&country=jp` で曲情報を取得する
4. 取得結果をプレビュー表示し、ユーザーが確認・修正してから保存する
5. 同一ユーザー内で同じ曲IDが登録済みなら重複として警告する

**自動取得する項目**：曲名、アーティスト名、アルバム名、ジャンル、ジャケット画像URL（文字列のみ保存し、MVPでは表示しない）、曲の長さ、リリース日、Apple Music URL、Apple曲ID

**フォールバック**

- URLの形式が不正、またはAPIで見つからない場合はエラーを表示し、手動入力に切り替えられる
- URLがない曲向けに、曲名・アーティスト名でのキーワード検索（iTunes Search API）から選んで登録できる
- すべて手動入力でも登録できる

**API利用の方針**：Lookupは登録時の都度呼び出しのみとし、取得結果はDBに保存して再取得しない。

## 機能要件：ユーザー項目・タグ

基本項目を標準で持ち、ユーザーが独自の項目を追加できるようにする。タグはフリーキーワードでその場で作成できる。

**基本項目**

| 項目 | 型 | 内容 |
| --- | --- | --- |
| 習熟度 | 選択肢 | 歌える／練習中／歌いたい |
| キー | 数値 | 自分に合うキー（-7〜+7程度） |
| タグ | 複数 | フリーキーワード |
| メモ | テキスト | 自由記述 |
| 最後に歌った日 | 日付 | 歌唱記録から自動更新 |
| 歌った回数 | 数値 | 歌唱記録から自動集計 |

**カスタム項目**

- ユーザーが項目名と型を定義して追加できる
- 型：テキスト、数値、選択肢（単一・複数）、日付、チェック
- 項目の並び順変更、非表示、削除ができる
- カスタム項目も検索・絞り込みの対象にする

**タグ**

- 入力欄にフリーキーワードを入れるとその場で新規タグになる
- 入力中に既存タグを候補表示する
- 前後スペースの除去、全角半角・大文字小文字の正規化で重複を防ぐ
- タグの名前変更、統合、削除ができる
- 登録時、Apple Musicのジャンルを初期タグとして提案する（外すこともできる）

**歌唱記録**：「今日歌った」ボタンで記録し、最後に歌った日と回数を更新する。記録時に以下も残せる。

- 歌いやすさ：5段階（1 余裕 〜 3 ふつう 〜 5 辛かった）。任意入力で、タップ1回で選べるようにする
- ひとことメモ：その日の調子や気づいたこと（任意）

曲ごとに直近の歌いやすさと平均を表示し、検索・並び替えの条件にも使えるようにする（例：「最近余裕だった曲」「辛かった曲を除外」）。

## 機能要件：検索・絞り込み

複数の条件を組み合わせて、サーバー側（DBのクエリ）で絞り込む。

- フリーワード：曲名、アーティスト名、アルバム名、メモ、タグ名を横断して検索（ひらがな・カタカナの揺れも吸収したい）
- タグ：複数選択し、AND／ORを切り替えられる。除外タグ（NOT）も指定できる
- 項目条件：習熟度、ジャンル、アーティスト、リリース年代、曲の長さ、キー、カスタム項目
- 並び替え：登録日、最後に歌った日（最近歌っていない順）、歌った回数、曲名、アーティスト名
- よく使う条件を名前付きで保存し、ワンタップで呼び出せる
- 「ランダムに1曲」：絞り込み結果から1曲を選ぶ。曲名が切り替わりながら止まるスロット演出を出し、「これにする」で開く・「もう一回」で選び直す（Issue #19。動きを減らす設定では演出なし）

## 認証・ユーザー管理

Supabase Authの無料プランに含まれる方式だけを使い、Row Level Security（RLS）でユーザーごとにデータを分離する。

**採用する方式**

- Googleアカウント（OAuth）でのログインを基本とする。メール送信が不要で、無料プランのソーシャルログインに含まれる
- 必要に応じてGitHubなど他のソーシャルログインを追加する（同じく無料プランに含まれる）

**採用しない方式**

| 方式 | 理由 |
| --- | --- |
| メール＋パスワード、マジックリンク | 確認メールやパスワード再設定のメール送信が必要。Supabase標準のメール送信はプロジェクトのチームメンバー宛てにしか届かず（1時間2通まで）、友人に使ってもらうには外部のSMTPサービスが必要になる |
| 電話番号（SMS） | 外部のSMS送信サービスの従量課金が発生する |
| 電話によるMFA | 有料アドオン（月75ドル〜） |
| SAML SSO | 無料プランに含まれない |
| Appleでサインイン | Apple Developer Programへの有料登録が必要 |

**その他**

- 友人への展開は招待制とし、許可したアカウントだけが使えるようにする（方法は未決事項を参照）
- 全テーブルにRLSを設定し、自分の`user_id`の行だけ読み書きできるようにする
- ログアウト、アカウント削除（データも全削除）ができる
- 無料プランの認証は月間アクティブユーザー5万人までで、想定規模には十分
- 将来メール認証を追加する場合は、無料枠のある外部SMTPサービスを接続する

参照元：[Supabase pricing](https://supabase.com/pricing)、[Supabase Auth：Send emails with custom SMTP](https://supabase.com/docs/guides/auth/auth-smtp)

## データモデル案

曲を中心に、タグは中間テーブル、カスタム項目は定義と値を分けて持つ。全テーブルに`user_id`を持たせRLSの基準にする。

| テーブル | 主なカラム | 備考 |
| --- | --- | --- |
| songs | id, user\_id, apple\_track\_id, title, artist, album, genre, artwork\_url, duration\_ms, release\_date, apple\_url, proficiency, song\_key, memo, last\_sung\_at, sung\_count, created\_at | (user\_id, apple\_track\_id) で一意 |
| tags | id, user\_id, name, normalized\_name | (user\_id, normalized\_name) で一意 |
| song\_tags | song\_id, tag\_id | 曲とタグの多対多 |
| custom\_fields | id, user\_id, name, field\_type, options, sort\_order | 項目の定義 |
| song\_field\_values | song\_id, field\_id, value (jsonb) | 型ごとの値をjsonbで保持 |
| sing\_logs | id, user\_id, song\_id, sung\_at, ease (1〜5, null可), note | 歌唱記録。easeは歌いやすさ（1 余裕〜5 辛かった） |
| saved\_searches | id, user\_id, name, conditions (jsonb) | 保存した検索条件 |

## 非機能要件

- コスト：無料枠内で運用する（DB・ホスティングともに月0円が目標）
- 端末：スマホとPCの両方に対応する。スマホは片手操作で検索結果まで3タップ以内、PCは3ペインで一覧と詳細を同時に扱える
- 性能：1,000曲規模で検索結果を1秒以内に表示する
- 可用性：店で開いたときに確実に使えること（下記のSupabase一時停止対策を含む）
- データ保全：JSON／CSVでエクスポート、JSONからインポートできる
- 移植性：DBアクセスはORM経由とし、PostgreSQL以外への移行余地を残す
- ドメイン：setlistic.laplusdestiny.com で公開する

## 技術構成とDB選定

DBと認証はSupabaseの無料プランを採用する。自分＋友人数十人の規模なら、5年分のデータでも容量は100MB前後に収まる見込み。

**構成案**

| 層 | 採用候補 |
| --- | --- |
| フロント・API | Next.js（Vercelにデプロイ） |
| DB | Supabase（PostgreSQL） |
| 認証 | Supabase Auth |
| ORM | Drizzle ORM（PostgreSQLとSQLiteの両方に対応） |
| 曲情報 | iTunes Lookup API／Search API |

**無料枠の比較**

|  | Supabase | Firebase（Firestore） | Cloudflare D1 |
| --- | --- | --- | --- |
| 容量 | 500MB | 1GiB | 5GB |
| 読み取り | 実質制限なし（転送5GB/月） | 5万ドキュメント/日 | 500万行/日 |
| 書き込み | 実質制限なし | 2万/日 | 10万行/日 |
| 認証 | 込み（5万MAU） | 込み | 別途実装 |
| 注意点 | 7日間操作がないと一時停止 | 複数タグのAND検索がクエリで書きにくい | 認証を自前で組む |

**データ量の試算**（1曲3KB、歌唱記録1件0.15KB、1人500曲・月30回で5年）

| 想定 | 5年後の容量 | 判定 |
| --- | --- | --- |
| 自分だけ（1,000曲） | 約3MB | どれでも余裕 |
| 友人30人 | 約52MB（Supabaseはシステム分込みで約100MB） | Supabaseで余裕 |
| 一般公開1,000人 | 約1.7GB | SupabaseとFirestoreは超過、D1なら収まる |

1人あたり5年で約1.7MBのため、Supabase無料枠では約260人分が上限の目安。システム領域の使用量は概算。

**一時停止への対策**：使わない期間が続くと一時停止するため、定期的にアクセスする仕組み（例：週1回のヘルスチェック）を入れるか、停止時はダッシュボードから再開する運用とする。

出典：[Supabase pricing](https://supabase.com/docs/pricing)、[Firebase pricing](https://firebase.google.com/pricing/?hl=fr)、[Cloudflare D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/)

### 対応サービスの拡張（Spotify・YouTube Music・Amazon Music）

共有URLからの登録を他サービスにも広げる。ただし、曲データの基準はApple Musicのカタログに統一し、他サービスのURLは「検索のヒント」として使う。

| サービス | 共有URLから取得できる情報 | 条件 | 対応方針 |
| --- | --- | --- | --- |
| Apple Music | 曲名、アーティスト、アルバム、ジャンル、ジャケット、長さ | 認証不要 | Lookupで確定（現行どおり） |
| Spotify | 曲名、アーティスト、アルバム、リリース日、長さ（曲ページのOGP） | 認証不要。自前のUser-Agent（`Setlistic/0.1 (+https://setlistic.laplusdestiny.com)`）で取得する。ブラウザのUAだとmetaタグのないページが返る | OGPで曲情報を取得し、iTunes Searchで Apple Music の表記にそろえる |
| YouTube Music | 曲名、アーティスト、アルバム、リリース日、長さ（自動生成動画の説明文） | Data API v3 はAPIキーのみ（任意）。無ければ watchページ → oEmbed | 説明文「Provided to YouTube by」を読み、無ければタイトル・チャンネル名を整形（「- Topic」除去、「(Official Music Video)」等の削除）して iTunes Search で照合する |
| Amazon Music | 公式の取得手段なし | Web APIはクローズドベータで承認制 | 自動取得は未対応と表示し、キーワード検索登録へ誘導する |

**処理の流れ**（詳細は GitHub Issue #4）

1. 貼り付けられたURLのドメインでサービスを判定する（album / playlist / artist のURLはエラー）
2. Apple Musicは従来どおりLookupで確定する
3. 他サービスは上表の方法で曲名・アーティスト名などを取り出し、iTunes Search APIで候補を探す（①芯の曲名＋アーティスト → 該当が無ければ ②芯の曲名のみ）
4. 候補との一致をシグナルの組み合わせで判定する
   - 確信あり：曲名一致 かつ（アーティスト一致 または 長さ±1秒とリリース日の両方一致）→ Apple Music の表記で入力欄を埋める
   - 要確認：曲名・アーティスト・長さのうち2つ以上が一致 → 候補（最大3件）か取得元の表記から選ぶ
   - 見つからず → 取得元の表記で入力欄を埋めて、確認・修正してもらう
5. どの場合もユーザーが確認画面で「セトリに追加」を押すまで保存しない
6. 元のURL（追跡パラメータを落とした `https://open.spotify.com/track/{id}` / `https://music.youtube.com/watch?v={id}`）とサービス名を「登録元リンク」として保存する。重複判定は iTunes の曲IDを優先し、無ければ登録元のサービス＋URLで見る

**前提と注意**

- Odesli（song.link）による相互変換は、公開APIが終了し新規キー発行も停止しているため採用しない
- Spotifyの開発者向け条件は2026年2月の変更で厳しくなった（Development ModeはオーナーのPremium契約が必須）ため、Spotify Web APIは使わない
- 取得元のページは登録時に1回だけ読み、ジャケット画像（`og:image`・サムネイル）は保存も表示もしない。ページの構造が変わると取れなくなるため、取れないときは「曲名で探す」へ誘導する
- 他サービスからの取得精度はApple Musicより下がるため、確認画面を必ず挟む

## 法的な留意事項

本節は公開情報をもとにした整理であり、法的助言ではない。一般公開や有料化の前に専門家へ確認すること。

**Apple関連**

- 曲名・アーティスト名・曲IDの保存：Apple公式のLookup APIによる、カタログとの対応付け用途に沿って利用する。
- ジャケット画像：MVPでは表示しない。画像そのものは保存せず、APIが返す画像URLの文字列のみ保存する。将来表示する場合は、Apple承認のバッジ（Apple Musicへのリンク）を画像の近くに置き、娯楽目的や他の商品・サービスの宣伝には使わない。
- 試聴音源（previewUrl）：MVPでは使わない。将来使う場合は「provided courtesy of iTunes」の表記を入れ、ストリーミングのみとし、保存・キャッシュ・同期はしない。
- API利用：Search APIは約20回/分が目安。登録時のみ呼び出し、取得結果はDBに保存して再取得しない。
- 名称・ロゴ：アプリ名・アイコン・画面上の見出しに「Apple Music」等のApple商標を単独で使わない。Apple表示は公式バッジに限る。
- 参照元：[iTunes Search API（Apple Performance Partners）](https://performance-partners.apple.com/search-api)

**ユーザーデータ**

- メールアドレス等の個人情報は個人情報保護法の対象。利用目的、第三者への提供をしないこと、アカウント削除（全データ削除）の手段を明記したプライバシーポリシーを用意する。
- 認証はSupabase Authを使い、パスワードを自前で保存しない。
- データの保存先はSupabaseのTokyoリージョンを候補とし、国外移転の説明を簡単にする。
- 友人への展開は招待制とし、不特定多数に公開しない。

**コンテンツ（歌詞・共有）**

- メモ欄に歌詞を書く運用は、個人が私的に利用する範囲を想定する。
- 将来「友人との曲リスト共有」を入れる場合は、メモ欄を共有対象から外すか、歌詞の全文掲載を禁止する注意書きを利用規約に入れる。
- ユーザーが文章や画像をアップロードできる機能を入れる場合は、利用規約で第三者の著作物の無断投稿を禁止し、削除申請の窓口を設ける。
