# 実装計画

MVPのゴールは「Apple MusicのURLを貼って登録し、タグと項目で探せる。自分のアカウントでログインしてスマホとPCの両方で使える」こと。フェーズごとに受け入れ条件を満たしたらオーナーに報告して次へ進む。

## Phase 0：土台づくり

- Next.js（App Router, TypeScript, ESLint, Prettier）のプロジェクト作成
- Supabase プロジェクト（Tokyoリージョン候補）と接続設定、`.env.example`
- Drizzle 導入、`docs/schema-draft.sql` を Drizzle スキーマに移植してマイグレーション生成・適用
- デザイントークン（`docs/design-system.md`）と Google Fonts（Zen Kaku Gothic New / Klee One）の設定
- アイコン類を `public/` に配置し、PWA manifest、`apple-touch-icon`、favicon を設定
- テスト環境（ユニットテスト用ランナー）と CI（lint・型チェック・テスト）
- Vercel へのデプロイと `setlistic.laplusdestiny.com` の割り当て

**受け入れ条件**：空のトップページが本番URLで開ける。マイグレーションでテーブルとRLSが作られている。ホーム画面に追加するとSetlisticのアイコンで表示される。

## Phase 1：認証

- Supabase Auth の Google OAuth 設定（Google Cloud の OAuth クライアント作成、リダイレクトURLに本番・ローカル・Vercelプレビューを登録）
- `/login`（モック01。メールアドレス欄とログインリンク送信は作らず、「Googleでサインイン」だけにする）、OAuthコールバック、ログアウト、未ログイン時のリダイレクト（middleware）
- 新規登録の制限（招待制の前段として、許可したメールアドレスのGoogleアカウント以外は使えないようにする）
- 初回ログイン時に `user_settings` と既定のタググループ・タグを作る（採用する場合）

**受け入れ条件**：オーナーのGoogleアカウントでログインできる。許可していないGoogleアカウントではデータを作れない。別アカウントでは他人のデータが一切見えないことを、RLSの自動テストで確認している。

## Phase 2：曲登録

- Apple Music URL パーサー（純粋関数）
  - `music.apple.com/{国}/album/{名前}/{アルバムID}?i={曲ID}`
  - `music.apple.com/{国}/song/{名前}/{曲ID}`
  - 国コード違い、`?l=` などの追加クエリ、末尾スラッシュを吸収
- iTunes Lookup API（`https://itunes.apple.com/lookup?id={曲ID}&country=jp`）をサーバー側から呼ぶ Route Handler / Server Action
- フォールバック：iTunes Search API（`https://itunes.apple.com/search?term=...&country=jp&media=music&entity=song`）によるキーワード検索登録、手動入力
- 登録確認画面（モック05 / PC-02）：取得結果の修正、タグ付け、キー、カスタム項目、メモ
- 重複警告（同じ `apple_track_id`）
- 登録時にApple Musicのジャンルを初期タグとして提案（外せる）
- `/add?url=` で開いたとき、URL欄に入った状態から始める
- PCの「まとめて登録」（複数URL）

**受け入れ条件**：上記2形式のURLと国コード違いのテストが通る。URLを貼ってから保存まで、スマホで3タップ程度で終わる。APIに見つからない曲も検索か手動で登録できる。

## Phase 3：一覧・詳細・編集

- ホーム（モック02 / PC-01）：曲一覧、件数、並び替え、フィルターチップ
- 曲詳細（モック06 / PCの詳細パネル）：表示と編集、削除（確認あり）、「Apple Musicで開く」
- 歌唱記録：「今日歌った！」で記録、歌いやすさ1〜5（任意）、ひとことメモ。`last_sung_at` / `sung_count` の更新
- PCの3ペイン：一覧で選んだ曲を横の詳細パネルに出し、遷移しない
- 曲0件のときの表示

**受け入れ条件**：登録した曲がスマホとPCの両方で一覧・詳細に出る。歌唱記録を付けると最後に歌った日と回数が変わり、記録を消すと元に戻る。

## Phase 4：検索・絞り込み

- 検索条件→クエリ変換を純粋関数にしてテスト
- フリーワード：曲名、アーティスト名、アルバム名、メモ、タグ名を横断
- タグ：複数選択、AND／OR切り替え、除外（NOT）
- 項目条件：習熟度、ジャンル、アーティスト、リリース年代、曲の長さ、キー、カスタム項目、直近の歌いやすさ
- 並び替え：登録日、最後に歌った日（最近歌っていない順）、歌った回数、曲名、アーティスト名
- 検索条件の保存と呼び出し
- 「ランダムに1曲」
- 検索はサーバー側（DBのクエリ）で行う

**受け入れ条件**：1,000曲のテストデータで、検索結果が1秒以内に出る。「十八番 AND 盛り上げ、ただしバラードを除く」のような条件が正しく絞り込める。

## Phase 5：タグ管理・設定・データ

- タグ管理（モック08 / PC-03）：探す／管理の切り替え、名前変更、統合、削除、並べ替え（グループ・別名は採用する場合）
- タグ入力：既存タグの候補表示、Enterで新規作成、正規化（NFKC・前後空白・英字の大小）で重複を防ぐ
- 設定（モック07 / PC-04）：カスタム項目の追加・編集・並べ替え・非表示・削除、表示設定、登録時に付けるタグ
- エクスポート（JSON / CSV）、JSONからのインポート
- アカウント削除（全データ削除）
- 利用規約・プライバシーポリシーのページ（文面はオーナーと相談）

**受け入れ条件**：タグを統合すると、両方のタグが付いていた曲が1つのタグにまとまる。エクスポートしたJSONを別アカウントにインポートすると同じ内容になる。アカウント削除後、そのユーザーの行が全テーブルから消えている。

## Phase 6：運用

- Supabase無料プランの一時停止（7日間操作がないと停止）への対策（方法はオーナー確認）
- エラー監視の最低限（Vercelのログで足りるか確認）
- 実機確認：iPhone Safari のホーム画面追加、暗い店内での視認性

## MVPの対象外（作らない）

- ジャケット画像の表示、試聴
- Spotify・YouTube Music・Amazon Music のURL対応（要件定義書に方針あり。MVP後）
- Siriショートカット（ただし `/add?url=` は Phase 2 で用意する）
- 友人との曲リスト共有
- DAM・JOYSOUNDの配信有無の自動取得
